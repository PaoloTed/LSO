• Namespace per creare mondi separati

•

•
processi, rete, filesystem, hostname, tabella di montaggio, utenti

•
Limitare uso di risorse:
•
CPU, RAM, I/O disco, traffico rete
•
Congelare processi
•
monitorare consumo

Namespace nel Kernel:
Nel kernel ogni processo ha uno PID reale (“global PID”)
I PID namespaces formano un albero (global →figlio →nipote)
Il processo appartiene solo al nodo foglia

Overlay Filesystems

OverlayFS è un filesystem “a strati” (union filesystem) usato dai 
container per combinare:
•
uno o più layer in sola lettura (immagini)
•
un layer in scrittura (container)

Principio fondamentale: Copy-on-Write
•
Quando il container modifica un file:
•
Il file non viene cambiato nel layer immagine (lowerdir, RO)
•
OverlayFS copia il file nell’upperdir (RW)
•
La VM / container vede solo la versione modificata
•
Le modifiche restano isolate nel layer superiore senza mai toccare 
l’immagine originale in sola lettura.
•
Vantaggi
•
Avvio velocissimo (le immagini sono RO, condivise tra container)
•
Poco spazio occupato (solo le modifiche sono salvate)
•
Rollback immediato (basta cancellare l’upperdir)
•
Massima riproducibilità (la base non cambia mai)

Overlay Filesystems

Esempio
•
mkdir lower upper work merged
•
echo “Hello DAL LOWER" > lower/file.txt
•
sudo mount -t overlay overlay \
-o lowerdir=lower,upperdir=upper,workdir=work merged
•
cat merged/file.txt //hello dal lower
•
echo "MODIFICATO DAL CONTAINER" > merged/file.txt
•
cat upper/file.txt      # <-- Esiste ed è modificato
•
cat lower/file.txt      # <-- Rimane invariato
•
rm merged/file.txt  # solo per upper è cancellato
•
ls -a upper # si vede .wh.file.txt, è whiteout cioè nasconde il file lower
•
sudo umount merged
•
rm -rf lower upper work merged
