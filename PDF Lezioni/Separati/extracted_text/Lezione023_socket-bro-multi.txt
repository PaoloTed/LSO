Broadcast e Multicast

Broadcast
Invio di pacchetti a tutti i nodi di una rete locale. Non richiede iscrizione: 
ogni host sulla subnet li riceve.

Multicast
Invio di pacchetti a un gruppo selezionato di destinatari che si iscrivono 
a uno specifico indirizzo multicast.

Il broadcast esiste solo in IPv4 e solo con pacchetti non orientati alla 
connessione (UDP)

Il multicast esiste solo su protocolli datagram (UDP)

In IPv6 non esiste il broadcast. È stato eliminato e sostituito dal 
multicast.


Broadcast
Invio di pacchetti a tutti i nodi di una rete locale. Non richiede iscrizione: 
ogni host sulla subnet li riceve.

Indirizzo usato è il broadcast della subnet, es.:192.168.1.255 per la rete 
192.168.1.0/24 oppure broadcast globale 255.255.255.255 (spesso 
bloccato dai router).
Sender (mittente):
1.socket(AF_INET, SOCK_DGRAM, 0)
2.setsockopt(..., SO_BROADCAST, ...) →abilitato esplicitamente
3.Mandare il pacchetto a xxx.xxx.xxx.255:porta con sendto()
Receiver (ricevitore):
1.socket(AF_INET, SOCK_DGRAM, 0)
2.bind() su:
1. INADDR_ANY
2. e la stessa porta
3.Ricevere con recvfrom()

Sender
#define BROADCAST_ADDR “255.255.255.255“ //broadcast limitato
int main() {
int sock; struct sockaddr_in addr; char *msg = "Hello broadcast!";
// 1. Crea socket UDP
sock = socket(AF_INET, SOCK_DGRAM, 0);
if (sock < 0) { perror("socket"); exit(1);}
// 2. Abilita il broadcast
int yes = 1;
if (setsockopt(sock, SOL_SOCKET, SO_BROADCAST, &yes, sizeof(yes)) < 0) {
perror("SO_BROADCAST"); exit(1); }
// 3. Imposta indirizzo broadcast destinazione
memset(&addr, 0, sizeof(addr));
addr.sin_family = AF_INET; addr.sin_port = htons(PORT);
addr.sin_addr.s_addr = inet_addr(BROADCAST_ADDR);
// 4. Invia periodicamente
while (1) {
if (sendto(sock, msg, strlen(msg), 0, (struct sockaddr*)&addr, sizeof(addr)) < 0) {
perror("sendto"); exit(1);}
printf("Inviato broadcast: %s\n", msg); sleep(1);
}
return 0; }

È il vero broadcast della rete (es. 192.168.29.255).
Arriva a tutti gli host nella stessa subnet (LAN reale o rete virtuale VMware).
Dipende dall'indirizzo assegnato dal DHCP della macchina/VM.

NAT (Network Address Translation)
Tecnica che mappa gli indirizzi di una rete privata verso l’esterno usando l’indirizzo 
del router. Il router NAT riscrive gli indirizzi sorgente/destinazione dei pacchetti.
Attenzione: NAT non inoltra broadcast né multicast, quindi il traffico broadcast resta 
sempre dentro la rete privata (incluso il NAT virtuale di VMware)
Modalità Bridged
La VM entra nella rete reale: riceve un IP dal router fisico (es. 192.168.1.x).
In questa modalità il broadcast di subnet (es. 192.168.1.255) può raggiungere tutti i 
PC della LAN reale.
Attenzione: su Wi-Fi il bridging può essere limitato dai driver: alcuni broadcast 
potrebbero non essere inoltrati alla VM.
Broadcast di subnet
È il vero broadcast della rete (es. 192.168.29.255).
Arriva a tutti gli host nella stessa subnet (LAN reale o rete virtuale VMware).
Dipende dall'indirizzo assegnato dal DHCP della macchina/VM.

Il multicast è un meccanismo in cui un processo invia un pacchetto 
UDP a un gruppo di destinatari identificati da un indirizzo IP speciale.
I processi che vogliono ricevere questi pacchetti devono iscriversi al 
gruppo (join) tramite la socket option: IP_ADD_MEMBERSHIP

Multicast
IGMP JOIN: come un host entra in un gruppo multicast
IGMP (Internet Group Management Protocol):  È il protocollo con cui un 
host annuncia al router locale di voler ricevere un gruppo multicast.
Processo di JOIN (host → router)
• L’applicazione invoca IP_ADD_MEMBERSHIP
• Il kernel invia un IGMP Report al gruppo (JOIN)
• Il router registra che su quella sottorete ci sono membri del gruppo
• Il router inizierà a richiedere il flusso (upstream) tramite PIM 
(Protocolo Independent Multicast)
Permette alla rete di sapere chi vuole cosa, evitando di inviare 
multicast a chi non è interessato
[Host] --IGMP--> [Router A] --PIM--> [Router B] --PIM--> [Router C] ←Sorgente

Multicast
PIM: come i router distribuiscono il multicast tra sottoreti
PIM (Protocol Independent Multicast)
È il protocollo con cui i router costruiscono l’albero di distribuzione dei flussi 
multicast tra le sottoreti

Cosa fa PIM
- decide su quali interfacce inviare il flusso multicast
- collega tra loro più router formando un albero
- aggiorna l’albero in base ai JOIN/LEAVE IGMP delle sottoreti
Cosa NON fa PIM
non vede gli host singoli (non può filtrare indirizzi IP di host) controlla solo 
interfacce / sottoreti, non LAN interne
Scopo
Propagare i pacchetti multicast solo verso le sottoreti che li hanno 
richiesti, evitando traffico inutile.

Multicast
Quando NON ci sono router o switch: multicast “senza controllo”
Nessuno interpreta IGMP
In una rete senza router multicast e senza switch con IGMP snooping:
- gli IGMP Report NON vengono letti da nessuno
- non esiste una membership list nella rete
- non si formano alberi PIM (non ci sono router)
Risultato sulla distribuzione
- mezzo fisico (bus/hub/Wi-Fi ) copia tutti i pacchetti multicast a tutti gli host
- JOIN serve solo al kernel per decidere se consegnare o scartare il pacchetto
Conclusione
Il multicast si comporta come un broadcast esteso, senza filtraggio fisico

Il ruolo degli switch: IGMP Snooping
Che cos’è IGMP Snooping?
Lo switch “spia” (snoop) i messaggi IGMP tra host e router, anche se non è un 
partecipante ufficiale
Cosa fa lo switch con lo snooping
- costruisce una tabella porta 
gruppo
- inoltra ogni gruppo multicast solo alle porte interessate
- evita di inondare la rete con traffico inutilmente
- può filtrare host specifici (su base porta o IP/ACL)
Scopo
Ottimizzare il multicast nella LAN:
- Multicast → solo alle porte con host iscritti
- Niente più broadcast verso tutta la LAN

In sintesi …
Host:
Fa JOIN/LEAVE (IGMP) e riceve il traffico desiderato.
Router (PIM):
- Costruisce l’albero multicast tra sottoreti
- Gestisce dove far passare il flusso
Switch (IGMP Snooping):
- Filtra la distribuzione nella LAN.
- Decide quali porte ricevono il flusso
Reti senza router/switch:
Nessun controllo
