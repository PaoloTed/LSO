Virtualizzazione
Concetti base
Definizione
•
Per virtualizzazione si intende la creazione di una versione virtuale di 
una risorsa normalmente fornita fisicamente  
•
La risorsa può essere:
CPU • Memoria • Disco • Schede di rete • sistemi operativi
•
È possibile eseguire, su una sola macchina (detta sistema host), altri 
sistemi operativi (detti sistemi guest) simultaneamente:
• Es. mettendo a disposizione un sistema Windows e un sistema Linux 
contemporaneamente.

Virtualizzazione
Tipi di “virtualizzazioni”

Astrazione: L’astrazione è il processo con cui si rappresenta un oggetto reale 
(risorsa fisica) tramite un modello semplificato (risorsa virtuale), che: mette in 
evidenza solo le proprietà utili all’utilizzatore nasconde i dettagli implementativi 
non necessari. Es., tipi di dato (int, float, …) nascondono la loro rappresentazione 
binaria in memoria.

Linguaggi di programmazione: Un programma scritto può essere eseguito su 
architetture diverse grazie a una macchina virtuale (es. java virtual machine) che 
interpreta o traduce le istruzioni, indipendentemente da sistema operativo e 
hardware.

Virtualizzazione a livello di processo: Nei sistemi multitasking, più processi 
possono essere eseguiti contemporaneamente. Ogni processo vede un proprio 
ambiente virtuale dedicato (CPU, memoria, dispositivi), pur condividendo le 
risorse fisiche. Questa forma di virtualizzazione è realizzata dal kernel del 
sistema operativo.

Virtualizzazione
Virtualizzazione di Sistema

Piattaforma hardware può eseguire contemporaneamente più macchine virtuali 
(VM). Ogni VM fornisce un ambiente isolato, composto da un proprio sistema 
operativo e dalle applicazioni che vi girano.

La condivisione dell’hardware è gestita da un componente centrale chiamato 
Virtual Machine Monitor (VMM) o hypervisor, che: 
•
crea e gestisce le VM
•
isola le VM tra loro
•
arbitra l’accesso alle risorse fisiche (CPU, memoria, I/O)

Il VMM è il mediatore unico nelle interazioni tra le macchine virtuali e l’hardware 
sottostante

Motivazioni 
•
Isolamento: software difettoso o dannoso non tocca l’host
•
Testing: posso provare modifiche e poi tornare indietro
•
Portabilità: sposto una VM dove voglio
•
Consolidamento: più server sulla stessa macchina = meno costi

Rappresentazione
Come rappresento una macchina?

“Simulazione”
•
Rappresenta una macchina in modo astratto, non fedele.
Serve a modellare il comportamento, non a eseguire codice reale.
→ Utile per studio, non per esecuzione di programmi reali.
Esempio: simulatori di rete, modelli di protocolli.

“Emulazione”
•
Riproduco un’architettura hardware diversa da quella reale.
Così posso eseguire programmi compilati per un’altra CPU.
→ Lenta perché il codice viene interpretato/convertito.
Esempio: QEMU (Quick EMUlator) che emula ARM su x86
•
grande flessibilità, bassa efficienza.

“Virtualizzazione”
•
Faccio girare più sistemi operativi della stessa architettura sull’hardware reale.
Non simula la CPU → i guest girano nativamente.
→ Molto più veloce dell’emulazione.

Virtualizzazione
Come implemento la virtualizzazione hardware? 

Virtualizzazione completa (full)
•
Il guest non sa di essere virtualizzato.
Pensa di parlare con hardware reale → massima compatibilità.
→ Overhead maggiore a causa della gestione trasparente dell’hardware.
•
Esempio: VMware ESXi

Paravirtualizzazione
•
Il guest sa di essere virtualizzato e collabora con l’hypervisor tramite API speciali. Meno 
overhead, ma richiede OS modificati.
Esempio storico: Xen paravirtualizzato.
•
Oggi la parav viene usata come ottimizzazione (es. virtio), non come modello puro.

Virtualizzazione assistita da hardware
•
Le CPU (Intel VT-x, AMD-V, ARM Virt. Ext.) forniscono istruzioni speciali
che rendono la virtualizzazione più efficiente.
•
→ È la base della virtualizzazione moderna.
→ Riduce costi di gestione del guest.
•
Oggi quasi tutte le VM usano questo modello.

Gestione delle risorse nella virtualizzazione
Gestione delle risorse (CPU, RAM, Storage, Rete)
•
L’hypervisor assegna risorse virtuali alle VM (vCPU, vRAM, vDisk, vNIC)
•
Supporto all’overcommit: possono essere allocate più risorse virtuali di 
quelle fisiche
•
Scheduler CPU gestisce la contesa tra VM → possibili latenze
•
La memoria può essere ottimizzata tramite tecniche come:
• Ballooning (restituzione memoria all’host)
• Deduplica delle pagine (KSM)
•
Lo storage è astratto tramite dischi virtuali (es. VMDK, QCOW2)
•
Possibile allocazione dinamica delle risorse (scaling verticale delle VM)

Virtual Machine vs Container

Virtual Machine 
•
Ogni VM ha un proprio sistema operativo guest e kernel
•
Maggiore isolamento, ma più risorse richieste
•
Avvio lento, peso in GB
•
Gestita da un hypervisor

Container
•
Condivide il kernel dell’host
•
Isolamento a livello di processo (namespaces, cgroups)
•
Avvio rapidissimo, peso in MB
•
Gestito da un container runtime (Docker, containerd, Podman)

Virtualizzazione
Caso Linux
•
Hypervisor: KVM (Kernel-based Virtual Machine)
•
È integrato direttamente nel kernel Linux (hyp tipo 1)
•
Linux è quindi l’host nativo ed è implementato come un modulo del kernel
•
Si attiva solo quando una VM lo usa (es. QEMU, libvirt, Docker con KVM, 
Firecracker)
•
Il kernel Linux diventa un hypervisor usando le estensioni (intel VT-x/AMD-V)
•
Le VM sono processi user-space che accedono a KVM via /dev/kvm

---PAGE BREAK---
Virtualizzazione
Supporto Hardware
•
Il kernel diventa un hypervisor utilizzando le estensioni hardware di
virtualizzazione
•
AMD-V su AMD e le ARM Virtualization Extensions (livello EL2) su ARM
•
Es. in VT-x, oltre alle due modalità Kernel/User (ring 0, 3) vengono aggiunte 
le modalità 
•
VMX Root Mode → Hypervisor
•
VMX Non-Root Mode → Guest VM
•
In VMX Root Mode l’hypervisor può avere ring 0 e 3, come un SO normale 
(es. Linux + KVM → il kernel Linux è ring 0 nel root).
•
In VMX Non-Root Mode la VM ha i suoi ring 0 e 3, isolati dal root.

Virtualizzazione
Caso macOS (Apple Silicon)
•
Non ha un hypervisor nel kernel
•
Non entra in modalità hypervisor come Linux/KVM o Hyper-V
•
Usa Hypervisor.framework, un’API user-space
•
Le VM sono gestite da applicazioni user-space che usano
Hypervisor.framework (UTM, Docker Desktop, VMware Fusion) 
•
Il supporto hardware gestisce:
•
modalità hypervisor (EL2)
•
guest mode
•
Stage-2 paging (Stage-2 ARM)
•
Il kernel macOS resta in EL1 (non è un hypervisor)

VM vs Container
Virtualizzazione
•
Ogni VM ha un kernel
•
Boot lento
•
Pesante in RAM e CPU
•
Isolamento fortissimo
Containerizzazione:
•
Non emula hardware
•
Non c’è un kernel guest
•
Avvio immediato
•
Leggerissima
•
Isolamento tramite kernel host (non hardware)
